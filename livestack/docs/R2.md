# Cloudflare R2: how it works and how livestack uses it

R2 is Cloudflare's object storage. You put files ("objects") into folders-like containers ("buckets") and get them back over HTTPS.
It speaks the **Amazon S3 API**, so standard tools work unchanged: `boto3` (our `replay.py`), `rclone` (the server's TLS backup) and the AWS CLI.
The difference from S3 that matters here is that **downloads are free**. There are no egress fees, which is why replays live here.

---

## 1. The concepts in 2 minutes

| Concept | What it is | In this project |
|---|---|---|
| **Account ID** | 32-character id of your Cloudflare account. Part of the API address. | `R2_ACCOUNT_ID`, `STATE_R2_ACCOUNT_ID` (same value) |
| **S3 endpoint** | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, the API address for *all* your buckets. Region is always `auto`. | built by `replay.py`; `R2_ENDPOINT_URL` overrides it (EU buckets: `https://<ID>.eu.r2.cloudflarestorage.com`) |
| **Bucket** | A named container. Private by default: nobody can read it without a key or a signed link. | `lms-replays` (videos), `livestack-state` (server TLS backup) |
| **Object / key** | A file, and its full name inside the bucket. The `/` in a key just looks like folders. | `replays/2026/11/20261111-1900.mp4` |
| **Metadata** | Small key/value tags stored with the object. | `sha256` of the file, used to prove the upload is complete and correct |
| **API token** | Created in the dashboard. For S3 tools it gives you an **Access Key ID + Secret Access Key** pair. It can be limited to specific buckets and to object-only access. | one token per bucket (see §3) |
| **Presigned URL** | A normal HTTPS link with a signature and expiry time in it. Anyone holding it can GET that one object until it expires (max 7 days). It works only on the S3 endpoint, not on a custom domain. | how the LMS gives a logged-in student a replay (`replay.py presign`) |
| **Custom domain** | Makes a bucket **public** at `https://media.example.com/<key>`, served and cached through Cloudflare's CDN. The domain must be on Cloudflare. | optional, only for free/public videos |
| **r2.dev URL** | A public development URL Cloudflare can enable per bucket. It is rate-limited and not for production. | not used |
| **CORS** | Browser rule: JavaScript on `lms.example.com` may only read a file from another site if that site allows it. | `config/r2-cors.json` on `lms-replays` |
| **Multipart upload** | Large files are sent in parts (we use 64 MB parts, 4 at a time) and joined by R2. A failed part is retried on its own. | automatic in `replay.py upload` for files over 64 MB |

R2 is **strongly consistent**: as soon as an upload returns OK, a read or `verify` sees the new object.

### How a replay gets from OBS to a student

```
 OBS recording (MKV, PC)
   │  replay.py encode   H.264 CRF 23 + AAC, "faststart" (index at the front so playback starts instantly)
   ▼
 replay.mp4 (PC) ── sha256 ──┐
   │  replay.py upload       │ 64 MB parts, retries; skipped if the same sha256 is already there
   ▼                         │
 R2 bucket lms-replays: replays/2026/11/<session>.mp4   metadata sha256=…
   │  replay.py verify  ◄────┘ HEAD: size + sha256 must match → manifest state/replays/<session>.json
   │                              (livestack.py stop refuses to destroy the server without it)
   ▼
 LMS backend: presign(key, 1 h) ──► https://<ID>.r2.cloudflarestorage.com/lms-replays/replays/…?X-Amz-Signature=…
   ▼
 student's browser <video src=…>  (seeks with HTTP Range requests; R2 supports them)
```

## 2. What it costs

R2 bills storage plus the number of operations. **Downloads (egress) are free.**
These are the published list prices at the time of writing. **VERIFY** them on Cloudflare's R2 pricing page.

| Item | Free each month | Then |
|---|---|---|
| Storage (Standard) | 10 GB-month | about $0.015 per GB-month |
| Class A operations (writes, uploads, lists) | 1 million | about $4.50 per million |
| Class B operations (reads, HEAD) | 10 million | about $0.36 per million |
| Egress (viewers downloading) | unlimited | free |

For this project: ~22 sessions × ~2–3 GB of 2-hour replays is **~60 GB added per month**. Storage grows by about $1/month each month while you keep everything.
The operations stay far inside the free tier: one multipart upload is a few dozen Class A operations, and each viewer seek is one Class B read.
To cap the cost, add a **lifecycle rule** (bucket → *Settings → Object lifecycle rules*), e.g. delete `replays/` after 365 days, if your course policy allows it.

## 3. Setup (dashboard, about 15 minutes)

1. **Enable R2:** Cloudflare dashboard → *R2 Object Storage*. You'll be asked to add a payment method, even for the free tier.
2. **Account ID:** shown on the R2 overview page. Copy it into `.env` as `R2_ACCOUNT_ID` and `STATE_R2_ACCOUNT_ID`.
3. **Create the buckets** (*Create bucket*, location *Automatic*, storage class *Standard*):
   - `lms-replays`
   - `livestack-state`
4. **Create two API tokens:** *R2 → Manage API tokens → Create API token* (*User API token* is fine).
   Make them separate, so a stolen server can never touch the replays.

   | Token name | Permissions | Specify bucket(s) | Put in `.env` |
   |---|---|---|---|
   | `livestack-replays-pc` | **Object Read & Write** | Apply to specific buckets only → `lms-replays` | `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` |
   | `livestack-state-server` | **Object Read & Write** | Apply to specific buckets only → `livestack-state` | `STATE_R2_ACCESS_KEY_ID`, `STATE_R2_SECRET_ACCESS_KEY` |

   After *Create*, the page shows the **Access Key ID** and **Secret Access Key** once. Copy both straight into `.env`.
   Ignore the "Token value"; the S3 tools don't use it. **Never paste these into chat, email or git.** `.env` is git-ignored.
5. **CORS on `lms-replays`:** only needed if the LMS player fetches the video with JavaScript (hls.js, `fetch`, `crossorigin` attribute). A plain `<video src="…">` doesn't need it, but setting it is harmless.
   - Edit `config/r2-cors.json`: replace `https://lms.example.com` with your real LMS address. Several are allowed, e.g. `["https://lms.yoursite.com","https://www.yoursite.com"]`.
   - Dashboard: `lms-replays` → *Settings* → *CORS Policy* → *Add CORS policy* → paste the JSON → *Save*.
   - (`python control\replay.py cors` does the same through the API, but only with an **Admin Read & Write** token. Object tokens are not allowed to change bucket settings, and the command tells you so.)
6. **Choose how students get replays:**
   - **Presigned URLs (recommended, private):** nothing else to set up. The LMS backend makes a 1-hour link per student per view (§5).
   - **Public custom domain (only for free content):** `lms-replays` → *Settings → Custom Domains → Connect Domain* → `media.example.com`. Cloudflare creates the DNS record. Anyone with a link can watch.
7. **Budget alert:** *Manage Account → Billing → Notifications*, or set up a usage-based billing alert.

Then test it (§4).

## 4. Test it

### Without an R2 account (works today)

`tests/test_r2_emulated.py` runs the real `replay.py` code against **moto**, a local S3-compatible server:

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q tests\test_r2_emulated.py
```
It covers single and multipart (70 MB) upload, sha256 metadata, skip-if-identical, re-upload when the content changes, verify (size, sha256, missing), a presigned GET over plain HTTP, selftest, and the CORS file.
Last run 2026-11-11: all pass.

### With your real R2 (after §3)

```powershell
cd E:\Freelancing\QualifyIAStream\livestack
python control\replay.py selftest            # the PC's replay token against lms-replays
python control\replay.py selftest --state    # the server's token against livestack-state
```

Expected output:

```
R2 selftest: bucket 'lms-replays' at https://<ID>.r2.cloudflarestorage.com with R2_* credentials
  [PASS] bucket reachable  ok
  [PASS] write object      selftest/20261111T172024-28752.txt
  [PASS] read back         54 bytes match
  [PASS] presigned URL     plain HTTP GET with a 2-minute link works (this is what the LMS does)
  [PASS] delete object     test object removed
  [PASS] token scope       cannot open 'livestack-state' (403) - good, the token is scoped to one bucket
R2 selftest: all checks passed
```

`[WARN] token scope … CAN open` means the token was created for *all buckets*. Delete it, and create it again limited to one bucket.

Then a real video:

```powershell
python control\replay.py upload "E:\temp\replay.mp4" --key test/hello.mp4
python control\replay.py verify --key test/hello.mp4 --file "E:\temp\replay.mp4"   # OK ... size and sha256 match
python control\replay.py presign --key test/hello.mp4                               # open the link: it plays and seeks
```
Delete `test/hello.mp4` in the dashboard afterwards (bucket → object → *Delete*).

| selftest says | Fix |
|---|---|
| `403 … wrong …ACCESS_KEY_ID / SECRET, or token not allowed` | Re-copy both keys (no spaces or quotes). Check that the token's bucket list includes this bucket. |
| `404 … bucket 'x' does not exist` | The bucket name in `.env` (`R2_BUCKET` / `STATE_BUCKET`) must match the dashboard exactly. |
| `cannot reach R2` / `400` | Wrong `R2_ACCOUNT_ID` (copy it again from the R2 overview), or no internet. |
| `SignatureDoesNotMatch` | Wrong secret, or the PC's clock is off by minutes: *Settings → Time → Sync now*. |

## 5. For the LMS developer: serving replays

Store the object **key** (e.g. `replays/2026/11/20261111-1900.mp4`) with the lesson, not a URL.
When a logged-in, enrolled student opens the lesson, the backend makes a short-lived link:

```python
import boto3
s3 = boto3.client("s3", endpoint_url=f"https://{ACCOUNT_ID}.r2.cloudflarestorage.com",
                  aws_access_key_id=READ_KEY_ID, aws_secret_access_key=READ_SECRET, region_name="auto")
url = s3.generate_presigned_url("get_object",
                                Params={"Bucket": "lms-replays", "Key": key}, ExpiresIn=3600)
# <video src="{url}" controls preload="metadata"></video>
```

- Give the LMS its **own** token with **Object Read only** on `lms-replays`. It never needs write access.
- A link works for anyone who has it until it expires. Keep `ExpiresIn` short (1–4 h) and generate it per page view.
- Other languages: every AWS SDK has the same "presign GetObject" call (Node `@aws-sdk/s3-request-presigner`, PHP `createPresignedRequest`, Laravel `Storage::temporaryUrl`).
- If you need offline-proof DRM, R2 alone isn't enough; presigned links stop casual sharing, not screen recording.

## 6. How the server uses the state bucket

- `server/cert_sync.sh` runs on every boot. It restores `/etc/letsencrypt` from `livestack-state` with rclone, using the `STATE_R2_*` token, so a fresh server reuses the existing TLS certificate instead of requesting a new one. Let's Encrypt allows only 5 duplicate certificates per week, and we rebuild 5×/week.
- After a new or renewed certificate is issued, it pushes the folder back.
- The server never receives the `R2_*` replay token (`SERVER_ENV_KEYS` in `control/livestack.py`), so a compromised server cannot delete or overwrite replays.
